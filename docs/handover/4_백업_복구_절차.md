# 4. 백업·복구 절차

## 자동 백업이 하는 일

`/usr/local/sbin/kbc-backup` (원본 `scripts/backup.sh`) 이 매일 한국 시간 03:30 에 실행된다.

| 파일 (`/var/www/backups/kbc_auto/`) | 내용 | 주기 |
|---|---|---|
| `db_날짜_시각.sql.gz` | DB 전체 (서비스를 멈추지 않고 덤프) | 매일 |
| `files_날짜_시각.tar.gz` | 강사 사진 폴더, `user/.env`, `admin/.env` | 매일 |
| `code_날짜_시각.tar.gz` | 코드 전체 (vendor·캐시·세션·로그 제외) | 일요일 |

- 14일이 지난 파일은 자동 삭제된다. (`KEEP_DAYS`)
- 백업 폴더는 root 만 열 수 있다. (`.env` 에 비밀번호가 있으므로)
- **백업에 없는 것:** DB 계정과 권한(MySQL 시스템 설정), nginx·PHP-FPM 설정 → 1번 문서와 `docs/` 의 원본으로 다시 만든다.

> ⚠️ **지금 백업은 같은 서버 안에만 있다.** 서버가 통째로 고장 나면 백업도 함께 잃는다.
> 서버 밖 보관 위치(다른 서버, 클라우드 저장소, 회사 PC 등)는 **결정 필요**.
> 정하기 전까지는 최소한 주 1회 `db_`·`files_` 최신 파일을 안전한 곳으로 내려받는다.

## 정기 점검 (월 1회 권장)

```bash
sudo ls -lh /var/www/backups/kbc_auto/ | tail          # 최근 파일이 매일 생기는지
sudo tail -5 /var/log/kbc-backup.log                   # "백업 완료" 줄
sudo sh -c 'for f in /var/www/backups/kbc_auto/*.gz; do gzip -t "$f" || echo "손상: $f"; done'
df -h /var/www                                          # 디스크 여유
```

지금 바로 한 번 더 백업하려면: `sudo /usr/local/sbin/kbc-backup` (코드까지: `sudo FULL=1 /usr/local/sbin/kbc-backup`)

## 복구 전에 반드시

1. **지금 상태를 먼저 백업한다.** `sudo FULL=1 /usr/local/sbin/kbc-backup` (복구를 잘못해도 되돌릴 수 있게)
2. 어느 날짜로 되돌릴지 정한다. 그 이후에 들어온 문의는 사라지므로 관리자 화면에서 목록을 따로 기록해 둔다.

아래 `TS` 는 백업 파일 이름의 날짜_시각이다. (예: `20261015_033001`)

## A. DB 만 되돌리기 (데이터를 잘못 지웠을 때)

```bash
TS=20261015_033001
B=/var/www/backups/kbc_auto

# 1) 먼저 시험용 DB 로 풀어서 내용 확인
sudo sh -c "gunzip -c $B/db_$TS.sql.gz | sed 's/\`kbc_db\`/\`kbc_restore_test\`/g' | mysql"
sudo mysql -e "SELECT COUNT(*) FROM kbc_restore_test.consult_inquiries"

# 2) 맞으면 실제 DB 에 복원 (테이블을 백업 시점 내용으로 바꿈)
sudo sh -c "gunzip -c $B/db_$TS.sql.gz | mysql"

# 3) 시험용 DB 삭제
sudo mysql -e "DROP DATABASE kbc_restore_test"
```

DB 계정 권한은 그대로 유지된다.

## B. 강사 사진·`.env` 되돌리기

```bash
TS=20261015_033001
sudo tar -tzf /var/www/backups/kbc_auto/files_$TS.tar.gz          # 들어 있는 파일 확인
sudo tar -xzf /var/www/backups/kbc_auto/files_$TS.tar.gz -C /var/www/kbc
sudo chown -R www-data:www-data /var/www/kbc/user/public/uploads /var/www/kbc/user/.env /var/www/kbc/admin/.env
sudo chmod 640 /var/www/kbc/user/.env /var/www/kbc/admin/.env
```

## C. 코드 되돌리기

코드는 GitHub 저장소가 원본이다. 보통은 `git` 으로 되돌린다.

```bash
cd /var/www/kbc
sudo git log --oneline | head               # 되돌릴 변경(커밋) 확인
sudo git revert <커밋번호>                   # 그 변경을 취소하는 새 커밋을 만든다 (기록은 남음)
sudo chown -R www-data:www-data /var/www/kbc
```

DB 구조가 바뀐 변경(마이그레이션 추가)을 되돌릴 때는 개발자와 먼저 확인한다.

저장소를 쓸 수 없을 때는 `code_` 백업을 푼다.

```bash
sudo mkdir -p /var/www/restore && sudo tar -xzf /var/www/backups/kbc_auto/code_$TS.tar.gz -C /var/www/restore
# /var/www/restore/kbc 를 확인한 뒤 옮기고, user·admin 에서 composer install --no-dev
```

## D. 서버가 고장 나서 새 서버로 옮길 때

서버 밖에 보관한 최신 `db_`·`files_` (그리고 `code_` 또는 GitHub 저장소)가 필요하다.

1. 1번 설치 가이드 **1) ~ 3)** : 프로그램 설치, 코드 받기, DB·계정 만들기
2. 4) 대신 `files_` 백업을 풀어 **기존 `.env` 를 그대로 사용** (암호화 키 유지 → 관리자 2단계 인증 그대로)
   - DB 계정 비밀번호는 `.env` 에 적힌 값으로 만들거나, 새로 만든 뒤 `.env` 를 고친다.
3. 5) 대신 위 **A-2** 로 DB 복원 → 5)의 kbc_user 권한 부여
   - 코드가 백업보다 새 버전이면 `sudo -u www-data env database.defaultGroup=migrate php spark migrate`
4. 1번 설치 가이드 **7) ~ 11)** : PHP 전용 공간, nginx, SSL, 자동 백업, 확인

> ⚠️ **`admin/.env` 의 `encryption.key` 를 잃어버렸다면**
> 관리자들의 OTP 설정을 읽을 수 없다. 새 키를 만든 뒤(`php spark key:generate`)
> 관리자마다 `sudo -u www-data php spark admin:reset-2fa 아이디` 를 실행하고, 다음 로그인 때 다시 설정한다.
