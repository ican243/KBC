# 1. 설치 가이드 (새 서버)

Ubuntu 24.04 기준. 명령은 서버 관리자 권한(`sudo`)으로 실행한다.
`도메인` 은 실제 도메인으로 바꿔 읽는다. (예: `kbcacademy.co.kr`)

> 지금 개발 서버(kir1.cafe24.com)에서 쓰는 설정은 `docs/nginx/kbc-subpath.conf`, `docs/php-fpm/kbc.conf`, `docs/ops/cron.kbc` 에 있다.
> 이 문서의 도메인용 nginx 설정은 초안이며, 도메인 연결 때(6번 체크리스트) 실제로 적용하고 확인한다.

## 순서 한눈에 보기

```
1 프로그램 설치 → 2 코드 받기 → 3 DB·계정 → 4 .env 작성 → 5 테이블·기본 데이터
→ 6 첫 대표 관리자 → 7 PHP 전용 공간 → 8 nginx → 9 SSL → 10 자동 백업·로그 정리 → 11 확인
```

---

## 1) 필요한 프로그램

| 프로그램 | 버전 | 용도 |
|---|---|---|
| PHP (FPM) | 8.2 이상 (개발: 8.3) | 홈페이지 실행 |
| PHP 확장 | intl, mbstring, mysqli, gd, curl, xml | CodeIgniter4, 이미지 처리 |
| MySQL | 8.0 | DB |
| nginx | 1.24 | 웹 서버 |
| Composer | 2.x | PHP 라이브러리 설치 |
| certbot | - | SSL 인증서 (Let's Encrypt) |

```bash
sudo apt update
sudo apt install nginx mysql-server php8.3-fpm php8.3-cli php8.3-intl php8.3-mbstring \
     php8.3-mysql php8.3-gd php8.3-curl php8.3-xml composer certbot python3-certbot-nginx git
```

## 2) 코드 받기

```bash
sudo mkdir -p /var/www && cd /var/www
sudo git clone <저장소 주소> kbc
cd kbc/user  && sudo composer install --no-dev --optimize-autoloader
cd ../admin && sudo composer install --no-dev --optimize-autoloader
sudo chown -R www-data:www-data /var/www/kbc
```

- 강사 사진 폴더(`user/public/uploads/instructors/`)는 git 에 없다. 기존 서버에서 옮길 때는 4번 문서의 복원 절차를 따른다.
- `user/public/mockup/` 폴더가 있으면 디자인 시안이므로 삭제한다.

## 3) DB 와 계정

사이트는 목적별로 **서로 다른 DB 계정**을 쓴다. (한 계정이 뚫려도 피해를 줄이기 위해)

| 계정 | 사용처 | 권한 |
|---|---|---|
| kbc_user | 공개 홈페이지 | 콘텐츠 조회, 문의·알림기록 등록, 조회수 기록 (**문의 조회 불가**) |
| kbc_admin | 관리자 | kbc_db 조회·등록·수정·삭제 |
| kbc_migrate | 테이블 생성·변경 | kbc_db 전체 (마이그레이션 때만 사용) |

비밀번호는 계정마다 다르게, 20자 이상 무작위로 만든다. (예: `openssl rand -base64 24`)

```sql
-- sudo mysql 로 접속해서 실행
CREATE DATABASE kbc_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

CREATE USER 'kbc_user'@'localhost'    IDENTIFIED BY '비밀번호1';
CREATE USER 'kbc_admin'@'localhost'   IDENTIFIED BY '비밀번호2';
CREATE USER 'kbc_migrate'@'localhost' IDENTIFIED BY '비밀번호3';

GRANT SELECT, INSERT, UPDATE, DELETE ON kbc_db.* TO 'kbc_admin'@'localhost';
GRANT ALL PRIVILEGES ON kbc_db.* TO 'kbc_migrate'@'localhost';
```

kbc_user 는 테이블 단위로 권한을 주므로 **5) 테이블 생성 뒤에** 실행한다.

## 4) `.env` 작성

```bash
cd /var/www/kbc
sudo cp user/.env.example  user/.env
sudo cp admin/.env.example admin/.env
sudo chown www-data:www-data user/.env admin/.env && sudo chmod 640 user/.env admin/.env
```

`입력` 이라고 적힌 곳을 채운다.

| 파일 | 채울 항목 |
|---|---|
| user/.env | `app.baseURL`, kbc_user 비밀번호, `cookie.path`, 메일 계정(`email.SMTPUser`, `SMTPPass`, `fromEmail`) |
| admin/.env | `app.baseURL`, kbc_admin·kbc_migrate 비밀번호, `cookie.path`, `site.publicURL`, `encryption.key` |

암호화 키:
- **새로 설치:** `cd admin && sudo -u www-data php spark key:generate`
- **기존 서버에서 이전:** 기존 `admin/.env` 의 값을 그대로 옮긴다. (바꾸면 관리자 전원의 2단계 인증을 다시 설정해야 함)

## 5) 테이블 만들기·기본 데이터

```bash
cd /var/www/kbc/admin
sudo -u www-data env database.defaultGroup=migrate php spark migrate
sudo -u www-data php spark db:seed InitialContentSeeder
```

- `migrate` : 테이블 13개(관리용 `migrations` 포함)를 만든다. 코드가 바뀐 뒤에도 같은 명령으로 변경 사항만 적용된다.
- `InitialContentSeeder` : 교육과정 3개(확정 전), 강사 분야 5개, 사이트 설정 18개. 이미 있는 데이터는 건너뛴다.
- 기존 서버의 데이터를 옮길 때는 이 단계 대신 4번 문서의 DB 복원을 한다.

이제 kbc_user 권한을 준다.

```sql
GRANT SELECT ON kbc_db.courses       TO 'kbc_user'@'localhost';
GRANT SELECT ON kbc_db.instructors   TO 'kbc_user'@'localhost';
GRANT SELECT ON kbc_db.notices       TO 'kbc_user'@'localhost';
GRANT SELECT ON kbc_db.events        TO 'kbc_user'@'localhost';
GRANT SELECT ON kbc_db.faqs          TO 'kbc_user'@'localhost';
GRANT SELECT ON kbc_db.site_settings TO 'kbc_user'@'localhost';
GRANT INSERT ON kbc_db.consult_inquiries TO 'kbc_user'@'localhost';
GRANT INSERT ON kbc_db.partner_inquiries TO 'kbc_user'@'localhost';
GRANT INSERT ON kbc_db.notification_logs TO 'kbc_user'@'localhost';
GRANT SELECT, INSERT, UPDATE ON kbc_db.page_views TO 'kbc_user'@'localhost';
```

## 6) 첫 대표 관리자

```bash
cd /var/www/kbc/admin
sudo -u www-data php spark admin:create
```

아이디·이름·역할(owner)·비밀번호를 차례로 입력한다. 비밀번호는 화면에 보이지 않는다.
처음 로그인하면 2단계 인증(OTP 앱) 설정 화면이 나온다. 이후 계정은 관리자 화면 **관리자 계정** 메뉴에서 만든다.

## 7) PHP 전용 공간 (PHP-FPM pool)

다른 사이트와 분리된 전용 실행 공간을 쓴다. KBC 폴더 밖의 파일은 읽을 수 없게 막혀 있다.

```bash
sudo cp /var/www/kbc/docs/php-fpm/kbc.conf /etc/php/8.3/fpm/pool.d/kbc.conf
sudo php-fpm8.3 -t && sudo systemctl reload php8.3-fpm
ls -l /run/php/php8.3-fpm-kbc.sock     # 파일이 보이면 정상
```

## 8) nginx (초안 — 도메인 확정 후 적용)

`/etc/nginx/sites-available/kbc` 로 저장한다. SSL 줄은 9)에서 certbot 이 추가한다.

```nginx
# 공개 홈페이지
server {
    listen 80;
    listen [::]:80;
    server_name 도메인 www.도메인;

    root /var/www/kbc/user/public;
    index index.php;
    server_tokens off;

    access_log /var/log/nginx/kbc-user.access.log;
    error_log  /var/log/nginx/kbc-user.error.log;

    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/css application/javascript image/svg+xml application/xml text/plain;

    add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; form-action 'self'; frame-ancestors 'self'; base-uri 'self'; object-src 'none'" always;

    location / {
        expires 7d;   # 정적 파일 7일 캐시 (파일이 바뀌면 주소 뒤 ?v= 가 바뀜)
        try_files $uri $uri/ /index.php$is_args$args;
    }

    location = /index.php {
        expires off;
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root/index.php;
        fastcgi_pass unix:/run/php/php8.3-fpm-kbc.sock;
    }

    location ~ \.php$ { return 404; }
    location ~ /\.(?!well-known) { deny all; }
}
```

관리자 주소는 **결정 필요**:

| 방식 | 주소 | 설정 |
|---|---|---|
| A. 하위 도메인 (권장) | `https://admin.도메인/` | 위 블록을 복사해 `server_name admin.도메인;`, `root /var/www/kbc/admin/public;`, `expires` 두 줄 삭제, `client_max_body_size 8m;`, `add_header Cache-Control "no-store" always;`, `add_header X-Robots-Tag "noindex, nofollow" always;` 추가. `admin/.env` 의 `cookie.path = '/'` |
| B. 하위 경로 | `https://도메인/admin/` | `docs/nginx/kbc-subpath.conf` 의 `/kbc/admin/` 블록을 공개 홈페이지 server 블록 안에 넣고 `/kbc/admin/` → `/admin/` 으로 바꾼다. `admin/.env` 의 `cookie.path = '/admin/'` |

A 방식은 공개 홈페이지와 쿠키·경로가 완전히 분리되고, 필요하면 관리자만 IP 제한을 걸기 쉽다.

```bash
sudo ln -s /etc/nginx/sites-available/kbc /etc/nginx/sites-enabled/kbc
sudo nginx -t && sudo systemctl reload nginx
```

> 같은 서버에 다른 사이트가 있으면 `server_name` 을 반드시 적는다. 적지 않으면 다른 사이트의 기본(default_server) 블록으로 연결될 수 있다.

## 9) SSL 인증서

DNS 가 이 서버를 가리키는 것을 확인한 뒤 실행한다.

```bash
sudo certbot --nginx -d 도메인 -d www.도메인            # 관리자 A 방식이면 -d admin.도메인 추가
sudo certbot renew --dry-run                              # 자동 갱신 확인
```

## 10) 자동 백업·로그 정리

```bash
cd /var/www/kbc
sudo install -o root -g root -m 755 scripts/backup.sh       /usr/local/sbin/kbc-backup
sudo install -o root -g root -m 755 scripts/cleanup-logs.sh /usr/local/sbin/kbc-cleanup-logs
sudo install -o root -g root -m 644 docs/ops/cron.kbc       /etc/cron.d/kbc
sudo /usr/local/sbin/kbc-backup                              # 한 번 실행해서 확인
```

- 실행 파일은 root 만 고칠 수 있는 위치에 둔다. (웹 계정이 고칠 수 있는 파일을 root 로 실행하지 않기 위해)
- 예약 시각은 서버 시간대 기준이다. `docs/ops/cron.kbc` 는 서버가 UTC 일 때 한국 시간 03:30 / 04:00 이다. 서버가 한국 시간(KST)이면 `30 3` / `0 4` 로 고친다. (`timedatectl` 로 확인)
- 스크립트를 고친 뒤에는 위 `install` 명령을 다시 실행해야 적용된다.

## 11) 확인

| 확인 | 방법 | 정상 |
|---|---|---|
| 홈페이지 | 브라우저로 `https://도메인/` | 홈 화면 |
| 없는 주소 | `https://도메인/없는주소` | KBC 404 화면 |
| 관리자 | 관리자 주소 → 로그인 → OTP 설정 | 대시보드 |
| 문의 접수 | 상담 폼 제출 | 접수번호 화면 + 알림 메일 + 관리자 목록에 표시 |
| 권한 분리 | `mysql -u kbc_user -p -e "SELECT * FROM kbc_db.consult_inquiries"` | 거부(denied) |
| 오류 로그 | `user/writable/logs`, `admin/writable/logs` | 새 ERROR 없음 |
| 백업 | `ls /var/www/backups/kbc_auto/` | db_, files_ 파일 |

확인 뒤 시험으로 넣은 문의는 관리자 화면에서 삭제 처리한다.
