# 6. 도메인 이전 체크리스트

개발 주소(`kir1.cafe24.com/kbc/`)에서 회사 도메인으로 공개 전환할 때 순서대로 진행한다.
각 단계 전에 백업을 하고, 끝나면 체크한다.

| 항목 | 값 |
|---|---|
| 공개 홈페이지 도메인 | ______________________ |
| 관리자 주소 방식 (**결정 필요**) | □ A. `admin.도메인` (권장)  □ B. `도메인/admin/` |
| 서버 | □ 지금 서버 그대로  □ 새 서버 (먼저 1번 설치 가이드) |
| 진행일 / 진행자 | ______________________ |

---

## 0. 준비

- [ ] 도메인 구입, 도메인 관리 계정 정보를 3번 양식에 기록
- [ ] 백업: `sudo FULL=1 /usr/local/sbin/kbc-backup`
- [ ] 회사 확인이 끝난 항목 반영: `docs/qa/공개문구_검수표.md`, `docs/qa/채워야할_정보.md`
- [ ] 실기기 점검 완료: `docs/qa/실기기_점검표.md`
- [ ] 개인정보 처리방침 법무 검토 완료 → 관리자 **사이트 설정**에 시행일 입력
- [ ] 알림 메일 보내는 계정을 회사 메일로 준비 (SMTP 사용 설정, 애플리케이션 비밀번호)

## 1. DNS

- [ ] 도메인 관리 화면에서 A 레코드: `도메인`, `www` (A 방식이면 `admin` 도) → 서버 IP
- [ ] 연결 확인: `dig +short 도메인` 결과가 서버 IP (반영까지 수 분 ~ 수 시간)

## 2. nginx

- [ ] 1번 설치 가이드 8)의 설정으로 `/etc/nginx/sites-available/kbc` 작성, `server_name` 에 실제 도메인
- [ ] `sites-enabled` 연결 → `sudo nginx -t` → `sudo systemctl reload nginx`
- [ ] 지금 서버라면: 같은 서버의 다른 사이트(lambda 443 블록 등)가 `default_server` 로 새 도메인 요청을 가져가지 않는지 확인
      → `curl -sI http://도메인/` 응답이 KBC 인지 확인

## 3. SSL

- [ ] `sudo certbot --nginx -d 도메인 -d www.도메인` (A 방식이면 `-d admin.도메인` 추가)
- [ ] `sudo certbot renew --dry-run`
- [ ] `http://` 로 접속하면 `https://` 로 이동하는지 확인
- [ ] `www` 있는 주소와 없는 주소 중 하나로 통일 (다른 쪽은 301 이동) — 대표 주소: ________

## 4. `.env` 주소·쿠키

| 파일 | 항목 | 개발 값 | 바꿀 값 |
|---|---|---|---|
| user/.env | `app.baseURL` | `https://kir1.cafe24.com/kbc/` | `https://대표주소/` |
| user/.env | `cookie.path` | `/kbc/` | `/` |
| admin/.env | `app.baseURL` | `https://kir1.cafe24.com/kbc/admin/` | A: `https://admin.도메인/` · B: `https://대표주소/admin/` |
| admin/.env | `cookie.path` | `/kbc/admin/` | A: `/` · B: `/admin/` |
| admin/.env | `site.publicURL` | `https://kir1.cafe24.com/kbc/` | `https://대표주소/` |
| user/.env | `email.SMTPUser`, `SMTPPass`, `fromEmail` | 개발자 개인 메일 | 회사 메일 |

- [ ] 위 값 변경
- [ ] 관리자 **사이트 설정 > 새 문의 알림 받을 이메일** 을 회사 담당자 메일로 변경

## 5. 운영 모드

- [ ] `user/.env`, `admin/.env` 의 `CI_ENVIRONMENT = production`
      (오류 상세 숨김, robots.txt 가 검색 허용 + 사이트맵 안내로 바뀜)
- [ ] 캐시 비우기: `cd /var/www/kbc/user && sudo -u www-data php spark cache:clear` (admin 도 같이)

## 6. 개발 기간 설정 제거

- [ ] lambda 443 server 블록에서 `include snippets/kbc-subpath.conf;` 줄과 주석 삭제
      (새 서버로 옮겼다면 해당 없음)
- [ ] 개발용 접속 제한(Basic Auth) 삭제: `/etc/nginx/.htpasswd-kbc`
      - 공개 전 회사 확인 기간에 계속 잠가 둘 경우, 개발자와 **다른 아이디·비밀번호**로 새로 만든다
- [ ] 검색 차단 헤더 `X-Robots-Tag noindex` 는 공개 홈페이지 설정에서 빼고, 관리자에는 유지
- [ ] 예전 개발 주소 이동 설정 삭제: `/etc/nginx/sites-available/kbc-admin` (admin.kbc.test)
- [ ] `sudo nginx -t && sudo systemctl reload nginx`

## 7. HSTS (HTTPS 고정)

모든 주소가 HTTPS 로 정상 동작하는 것을 확인한 **뒤에** 추가한다. (한 번 적용되면 브라우저가 HTTP 로 접속하지 않음)

- [ ] 공개·관리자 server 블록에 `add_header Strict-Transport-Security "max-age=31536000" always;`
      (처음에는 `max-age=86400` 으로 하루 시험 후 늘리는 것을 권장)

## 8. 데이터 정리

- [ ] 디자인 시안 삭제: `sudo rm -rf /var/www/kbc/user/public/mockup`
- [ ] 개발 중 쌓인 조회수 초기화: `sudo mysql -e "TRUNCATE kbc_db.page_views"`
- [ ] 시험 문의 삭제 (관리자 화면에서 삭제 처리, 또는 DB 에서 완전 삭제)
      ```sql
      -- 개발 기간 시험 문의만 골라 확인한 뒤 삭제
      SELECT id, receipt_no, name, created_at FROM kbc_db.consult_inquiries;
      ```
- [ ] 시험 알림 기록 정리 (`notification_logs`)

## 9. 비밀번호 전부 교체

개발 기간에 개발자가 알던 비밀번호는 모두 바꾼다. 바꾼 뒤 3번 양식의 "전달 방법"대로 넘긴다.

- [ ] DB `kbc_user` → `user/.env` 반영
- [ ] DB `kbc_admin`, `kbc_migrate` → `admin/.env` 반영
      ```sql
      ALTER USER 'kbc_user'@'localhost' IDENTIFIED BY '새 비밀번호';
      ```
- [ ] DB `kbc` (개발용 DB 관리 계정) → `DROP USER 'kbc'@'localhost';` (또는 교체)
- [ ] 관리자 계정: 회사 대표 관리자 계정 생성 → 로그인·2단계 설정 확인 → 개발자 계정 **사용 중지**
- [ ] 알림 메일 계정 (4단계에서 회사 메일로 변경했으면 완료)
- [ ] 서버 접속(SSH) 키·비밀번호, 호스팅 계정 (회사 서버라면)
- [ ] 저장소(GitHub) 권한 이전, 개발 서버 배포 키 삭제
- [ ] `encryption.key` 는 **바꾸지 않는다** (바꾸면 관리자 2단계 인증 전부 재설정)

## 10. 공유·검색 등록

- [ ] 카카오 공유 디버거(developers.kakao.com/tool/debugger/sharing)에 대표 주소 입력 → 미리보기 이미지·제목 확인
- [ ] `https://대표주소/robots.txt` 에 `Sitemap:` 줄, `https://대표주소/sitemap.xml` 에 페이지 목록 확인
- [ ] 구글 서치 콘솔 등록, 사이트맵 제출
- [ ] 네이버 서치어드바이저 등록, 사이트맵 제출
- [ ] 소유 확인용 메타 태그를 요구하면 `user/app/Views/layouts/main.php` `<head>` 에 추가

## 11. 운영 설정

- [ ] 서버 밖 백업 보관 위치 결정·설정 (4번 문서)
- [ ] 문의 보존 기간 결정 → 사이트 설정 "문의 정보 보존 기간" 문구 + `admin/.env` `inquiry.retentionDays`
      → `php spark inquiry:purge --dry-run` 으로 확인 → `/etc/cron.d/kbc` 의 파기 줄 `#` 제거
- [ ] 자동 백업 예약 시각이 서버 시간대에 맞는지 확인 (1번 문서 10)

## 12. 최종 확인

| 확인 | 정상 |
|---|---|
| `https://대표주소/` 홈, 모든 메뉴 | 화면 정상, 로그인 창(Basic Auth) 안 뜸 |
| 휴대폰에서 홈·상담 신청 | 레이아웃 정상 |
| 상담 신청 1건 | 접수번호 → 회사 메일로 알림 → 관리자 목록 표시 → 확인 후 삭제 |
| 관리자 로그인 (회사 계정) | 비밀번호 + OTP |
| 담당자 계정으로 사이트 설정 주소 직접 입력 | 권한 없음 화면 |
| 없는 주소 | KBC 404 화면 |
| `curl -sI https://대표주소/` | `X-Robots-Tag` 없음, `Strict-Transport-Security` 있음 |
| `curl -sI https://관리자주소/` | `X-Robots-Tag: noindex` 있음 |
| 다음 날 | 자동 백업 파일 생성, `/var/log/kbc-backup.log` 정상 |
| 오류 로그 | `writable/logs` 에 새 ERROR 없음 |
